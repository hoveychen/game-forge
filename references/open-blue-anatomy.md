# Open Blue 拆解：一份让 Opus 做出惊艳游戏的设计文档

原文见 `exemplars/open-blue.md`。这份文档很可能是作者与 AI 多轮对话的产物（结尾残留「Yes — that split makes sense」）。也就是说，「想清楚这个游戏」这一步在交给编码 agent 之前已经完成了。

**来源存疑的提醒**：社区里流传的那些「像 GDD 的长 prompt」，常常是游戏做完之后反向整理出来的复用规格，不是最初的输入。Open Blue 是否一次喂进去、有没有多轮迭代，目前无法确认。拿它当「好规格长什么样」的样板没问题，但不要把它当成「写成这样就能一次成功」的证据。

## 它覆盖的七层

| 层 | 内容 | 作用 |
|---|---|---|
| 情感幻想 | 社畜崩溃，「I'm done」辞职下乡 | 所有设计都能回溯到一个「为什么」 |
| 第一个有分量的选择 | 三块地同价 $200,000，选的是生活方式 | 开局十分钟就有身份认同 |
| 世界与尺度 | 512×512、区域拓扑、地产边界的意义 | 限定空间规模 |
| 手感 | 相机 35°/45°、按键、角色 6–8 体素宽 | 替 AI 做掉几千个细碎决定 |
| 系统 | 9 个技能各 1–5 级具体内容 | 可直接实现的内容表 |
| 闭环 | 砍树→做箭→打猎→烹饪；第一个早晨流程；钱的来龙去脉 | 系统互相喂 |
| 边界 | MVP 清单、要回答的问题、未来扩展 | 定义什么叫做完 |

## 让它有效的写法

1. **校准锚点而非穷举。** 每个系统给一个带数字的例子（松树 3 级 7 下、5 级 5 下；篝火 3 树枝 + 1 火绒；种子 $4），AI 据此推出其余数值。
2. **大量「不要什么」。** 「钓鱼不是点水→等→出鱼」「种地比 Stardew 更实体」「不是所有东西都用方块」「没有天赋点」「避免纯平面拉伸」。每条都把 AI 从默认做法里拉出来一次。
3. **讲理由。** 同价是为了让选择关于生活方式；剩 $5,000 是为了「地多钱少」的心理落差；只做到 5 级是为了先证明生活本身有趣。未写明处，AI 能顺着理由做一致的决定。
4. **每种产出都有去处。** 木头→生火、做箭；鱼→烹饪、卖钱；钱→种子、工具；矿→打工具→提高采集效率。
5. **地理上小，系统上密。** 主动压规模，同时保证连通。
6. **锁住的未来。** 6–99 级在 UI 上可见但锁住，让 MVP 感觉像一个大游戏的开端。

## 它缺的东西（本 skill 补上的部分）

- 实现层几乎空白：技术栈、性能目标、架构都没写。
- 没有验收标准和主线通关定义。
- 没有开发顺序（行走骨架、里程碑）。
- 几秒尺度的手感写得很少。这在沙盒品类里不致命，换到动作类就是致命缺口。
- 一些机制是一笔带过的（「追踪脚印」「洪水以后可能成为机制」）。

## 注意：品类红利

Open Blue 的乐趣主要来自系统，系统写成数据表和规则正是 AI 最擅长的；体素美术能用代码生成，绕开了美术瓶颈。它的成功有一部分来自品类本身适合 AI，不能直接外推到所有品类。
