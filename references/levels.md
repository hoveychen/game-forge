# 怎么写关卡

只要玩家是在手工设计的空间里推进的——线性关卡、箱庭小关、地牢、银河城、开放世界里的地标和神庙、沙盒里摆好的地点——GDD 就要有一节「关卡」。它管三件事，各种结构都适用：

1. **知识链**：玩家要学会哪些东西，每样东西在哪里安全地看一次、在哪里考、在哪里换个情境再考，最后在哪里合起来用。
2. **空间结构**：挑战单元怎么连起来，玩家按什么顺序遇到它们，什么东西挡着他。
3. **挑战单元卡**：每个单元（一关、一间房、一个神庙、一处遭遇）里，玩家看到什么、先试什么错、靠哪个洞察过去。

「单元」是什么、顺序由谁决定、门槛是什么，各种结构差别很大。这些要从第 2 步拆解标杆时拆出来（见 `teardown.md` 的「关卡结构」一块），不要套用本文的某一种。节奏曲线一节管单元之间怎么排，这一节管每个单元里有没有东西。目前的范例只有一份箱庭地牢：`exemplars/juanbian-cards.md`。

## 一、为什么（一次实测）

卷边岛是一个 2D 塞尔达式小冒险：一张地上世界、一座 13 房的地牢、一个 Boss。GDD 写地牢时，每间房只有节奏表里的一行：「秒数 / 出什么 / 哇点」。14 行里有 3 行哇点是「—」，等于 GDD 自己承认这几间没有题。执行会话照着这张表把房间摆了出来，自动驾驶能通关。老板一试玩，发现了三个问题：

- **房间里没有题。** 有的房间，地图就摆在明处；有的房间只能隔着栅栏看，什么也做不了；还有一间是同一个动作做三遍。
- **Boss 的核心打法没人教过。** 蛀王一阶段要「卷起它所在的那条地毯，把它卷进卷筒」，可地牢后半段八间房一只蛀虫都没有。这个打法玩家第一次见，就是在 Boss 房里被考。
- **地牢是一条直线。** 地图、罗盘拿到了也没有用，钥匙几乎是拿了就用。

事后补的两轮检查都没抓到这些问题。一轮是开工 8 小时后追加进 GDD 的节奏条目（区域四拍、强度曲线、每房新元素不超过 2 个、相邻房组合不重复），逐条对照几乎全是「达标」。另一轮是逐房拿房间数据对 GDD 原文，18 间房和两个 Boss 判成「对得上」。两轮比的都是「实现和 GDD 一不一致」：GDD 没写题，空房间就照样过关。同一批追加条目里，写成具体数字的手感锚点，执行会话几乎逐条做到了。所以，写成具体内容的东西会被做出来，只写成规则的东西会被应付过去。后来补写了一版知识链和逐房谜题卡，上面三个问题当场全都看出来了。

## 二、先认清空间结构类型

| 类型 | 单元 | 玩家遇到单元的顺序 | 门槛 | 知识链怎么排 | 标杆的样子 |
|---|---|---|---|---|---|
| 线性关卡 / 箱庭小关 | 一关（关内再分段） | 设计者定 | 通关 | 一关一个新点子，关内走完「引入→发展→变化→收尾」；世界之间叠加 | 3D 马里奥一关围绕一个机关；奇诺比奥每关是一个转着镜头看的小箱庭 |
| 地牢 / 箱庭大关 | 房间 | 半固定：有环、有岔路 | 钥匙、开关、地牢道具 | 按房排；地牢道具在中段拿到，之后的房间围着它转 | 2D 塞尔达的地牢 |
| 银河城 | 房间和区域 | 玩家自选，受能力锁限制 | 能力 | 每个能力占一行；每个能力锁在拿到能力之前就被看到过，拿到之后要让几处旧地点换个样子 | 银河战士、空洞骑士；FPS 形式如银河战士 Prime |
| 开放世界 | 兴趣点：神庙、营地、地标谜题、遭遇 | 基本控制不了 | 软门槛：气候、敌人强度、体力、视野 | 不能靠顺序。核心动词在一个封闭的新手区集中教完；之后每个单元要么自带「安全地看一次」，要么不依赖还没教过的知识就能解 | 旷野之息：初始台地教完四个能力，神庙是自带教学的小谜题，地标靠视线吸引玩家 |
| 沙盒 | 情境：系统组合会碰撞出东西的地点和时刻 | 玩家自己定目标 | 资源、配方、工具档位 | 知识链是「系统之间能怎么组合」；卡写的是怎么布置环境，让玩家撞见这个组合 | 我的世界：第一晚逼你挖洞或造房 |

一个游戏常常是混合的：开放世界的塞尔达里，神兽和神庙是箱庭；银河城里的 Boss 房是一个小关卡。每一层按它自己的类型写。

## 三、知识链

写任何一个单元之前，先把玩家要学会的东西列成表。每条知识是一句玩家能说出口的话（「补丁有重量，压在踏板上能顶替人」「冲刺能穿过红色的激光」）：

| # | 知识 | 安全地看一次 | 第一次考 | 换情境再考 | 最后合起来用（Boss / 终局） |
|---|---|---|---|---|---|

通用的规矩：

- **每条知识都走「安全地看一次 → 考 → 换个情境再考」。** 「安全地看一次」是指在不会受伤、不会卡关的地方，完整地看到这个东西怎么动、怎么反应。
- **没教过的不考。** Boss 和终局的每一个打法，都要能在表里倒查到前面在哪里考过。
- **核心动词的每种用法都占一行。** 「卷」有搬、骑、碾、卷住敌人四种用法，就是四行。

顺序不由设计者决定的结构，要多查一步：

- **银河城**：把能力可能的获得顺序列出来（通常只有几种），每一种顺序下知识链都不能断。每个能力锁在玩家拿到能力之前，至少被他看到过一次，最好是一处他想去却去不了的地方。
- **开放世界**：列出新手区教会的那几条，其余每个单元在卡上写明它依赖哪几条知识。依赖新手区以外知识的单元，要么自己教（神庙式：入口一段安全的演示，后面才是考题），要么放在玩家通常会晚到的地方，并且有一个不依赖那条知识的笨办法。

## 四、空间结构图

用 ASCII 画出单元怎么连、门槛在哪，写进 GDD。按类型查这些：

- **线性**：世界图加每关的段落；每关的新点子写在图上。
- **地牢 / 箱庭**：至少有一个环或一条岔路，地图和钥匙才有意义；钥匙不在锁的隔壁拿到（教「钥匙」这个概念的那一间除外）；前半段要有一处「看得见、够不着」，拿到地牢道具后回来就能过去。
- **银河城**：标出每个能力锁，以及拿到能力后被重新打开的旧地点；从每个存档点出发都能看到至少一处还过不去的地方；捷径在玩家第一次绕远路回来以后才打开。
- **开放世界**：标出兴趣点的分布和密度（我希望玩家在任何地方骑马或滑翔 X 秒内就能看到下一个想去的东西），以及从高处能看到哪些地标。用地形挡住视线，让玩家走近了才发现下一个东西。软门槛写清楚是什么、怎么在远处就看出来（雪山要御寒、这片敌人是红色的）。
- **沙盒**：标出资源和危险的分布、玩家的第一个据点会建在哪，以及第一晚、第一次下矿这类强制情境发生在哪里。

## 五、挑战单元卡

每个单元一张卡，回答六件事：

| 项 | 写什么 |
|---|---|
| 进门已会 | 玩家到这里时已经掌握的知识，引用知识链编号。开放世界写「依赖」：做这个单元需要哪几条 |
| 一眼看到 | 第一眼看到的目标和障碍，最好是「看得到、够不着」。开放世界再加一句：玩家从多远、从哪里会注意到它 |
| 先试的错法 | 玩家最先会试的做法，以及它**怎样失败**。失败要让玩家亲眼看到，失败本身就是线索。单元要保证这个错法真的走不通 |
| 洞察 | 过这个单元要想通的那一句话，能从「错法为什么失败」推出来 |
| 线索 | 环境里有什么指向洞察：颜色、唯一能互动的东西、敌人站位、一句台词。只在没有可读线索时才用文字提示 |
| 教会 → 考 | 这里让玩家学会了哪条知识，后面在哪里考 |

单元有不同的类型，写法跟着变：

- **谜题单元**：六项写满。
- **战斗单元**：「洞察」写成这场仗的打法（谁先打、怎么用地形），直接写明是战斗单元，不硬凑啊哈。
- **放松单元**：在峰值之后，没有伤害，但要有一件可做的小事和一个笑点。
- **预告单元**：安全地看一次后面要考的东西。
- **探索奖励**（开放世界、银河城）：写清楚奖励是什么、玩家为什么会绕过来，以及从哪里能看到它。

用设计师的口吻写，不写成验收条款：「我希望玩家先踩一下踏板就往门口跑，门会在他眼前落下——踏板到门的距离要够远，这一跑一定来不及。」

写完以后，逐张卡回答两个问题：「先试的错法」真的会失败吗？一个只经历过前面那些单元的玩家，能不能从线索推到洞察？

## 六、写到多细

GDD 是执行会话唯一的输入，没写的单元就会被填成最平均的样子。

- **单元在 30 个以内**（一座地牢、一个十几关的世界、一张小银河城地图）：每个单元都写一张卡。
- **单元多的**（开放世界、大银河城）：新手区和第一个大区域写全卡；其余按单元种类各写一张模板卡，加 3–5 张写满的样例卡，再给一张分布表（每个区域每种单元几个、各依赖哪几条知识）。执行会话按模板和样例铺量。

13 个单元的卡大约 5–8k 字符。GDD 的长度上限为这一节放宽，卡不要删短。

## 七、单元之间：节奏规则

卡写完、知识链排通以后，再用下面这些规则检查单元的排列。它们只管排列，代替不了卡：

- **四拍**：每个区域（或每个世界、每个大关）定一个核心概念，按引入、发展、变化、收尾排。引入没有风险，变化让这个概念换一种用法，收尾把它推到最大。
- **每个单元新元素不超过 2 个**：第一次登场的敌人、机关、动词用法都算。
- **强度曲线**：峰值之后接一个放松单元；只有 Boss 这类峰可以长。
- **相邻单元的「主动词 + 对手 + 地形」组合不重复。**
- **节奏目标**：用「我希望」的口吻写，并写清怎么量。比如最长一段没有新东西的时间、最长一段什么都没发生的时间、每个核心动词被用在几种不同的情境里。开放世界改成按密度写：在任意位置，多久能看到或遇到下一个兴趣点。

规则之间会冲突，要在 GDD 里写明怎么取舍。卷边岛撞过一次：「第一次出现不能直接考」要求一种敌人先在没有危险的地方露面，「放松单元不出新敌人」又不让它出现在峰值之后的那间房里。写成「隔着栅栏、碰不到的预告不算放松单元里的新敌人」，这个冲突就不会发生。

## 八、手感锚点

动作类（含 FPS）的关卡靠手感撑起来，而手感数字是执行会话最会照做的东西，所以要写全，每项一个数字：

- **宽容机制**，每条写数值和理由：门口和墙角修正、坑边宽容、土狼时间和跳跃缓冲、动作输入缓冲、交互目标吸附、瞄准辅助的范围和强度、受击击退不把人推进坑里。
- **反馈清单**，每项单独可开关：命中停帧（普通 / 击杀 / Boss 分档，写上限）、白闪、击退、粒子、屏震（每种事件的像素或角度和帧数，沿冲击方向、逐帧衰减）、挤压拉伸、受击反馈、命中标记和击杀确认音、拾取飞向 HUD。
- **攻击前摇**：前摇时长 ≥ 0.25 秒反应时间 + 玩家应对动作生效的时间 + 余量。每种敌人写一行：前摇多长、怎么看出来（姿势和声音）、玩家用什么应对。同一屏或同一视野里同时出手的敌人要有上限。
- **镜头**：锁定、跟随还是第一人称；切屏多久；什么事件才推镜头；FPS 写视野角、灵敏度曲线、晃动幅度。

锚点从拆解里来，用名作校准，偏离的地方写出理由。

## 九、写进 GDD 的哪里

关卡一节放在节奏曲线之后，顺序是：结构类型和单元 → 知识链表 → 空间结构图 → 挑战单元卡（或模板卡、样例卡加分布表）→ 节奏规则和取舍。
