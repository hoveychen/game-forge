## 关键回帖原文（按主题）

**规模失控（最常见的烂尾原因）**
> 我最近在 vibe 写游戏, 到目前的结论就是, AI 根本无法完成一个体量稍微大一点的工程哪怕最开始设计的构架井井有条, 一旦游戏内容稍微多一点, 基本就脱离控制了.但如果是小体量的游戏, 真的很高效, 很快就可以看到成果且运行良好.你作为开发者, 必须非常清晰项目每一行代码

**拆 GDD、逐个系统实现**
> 放置类小游戏用 web 技术栈做最合适，先让 Claude Code 帮你拆分 GDD （游戏设计文档），把核心循环、数值系统分开逐步实现，别一上来就让它写全。美术资源直接用 kenney.nl 的免费素材，省掉 AI 生图的踩坑时间。

> #16 这文档太简单了。我们普通的小项目需求文档就几百行了，你要做个复杂的游戏只会更复杂。照着 SDLC 流程一点点往前推，前面需求文档 PRD 这一块反复和 AI 去头脑风暴，把细节都补全，再前进到 Design 这块。
（针对另一楼贴出的《木材大亨：H5 工业自动化版》GDD——"涵盖了实体定义、状态机逻辑、精确公式及 UI 架构"，2.5D 等轴测、竖屏 9:16）

**先要骨架/参照物，不要从零**
> 你要先找个框架模版呀，不能直接让它干。比如你想做的，你就 GitHub 上先找找竞品；找不到的话，也要找个通用框架，让它在其基础和文档上构建。

> 先创建一个目录，让 claude 用 godot 帮你搭建一个原型，然后用/brainstorm skill 进行头脑风暴，这个时候 AI 会像你提问，问你具体的细节，然后你让他只实现一个 最简单的原型 demo ，然后自己慢慢完善建模，玩法就行了

> 开发一般是设计、遵循 tdd 、构建环境反馈循环的原则，这样生成出来完整性会好一点。

**已上线者的经验**
> 纯 Vibe 开发的游戏已经在 Steam 上线了：WordJoy。个人经验有两点：一个是把 AI 当成工具，牢牢把握信全局进展的方向，你要明确做一个什么样的游戏出来；二是慢慢花时间与耐心磨出来。

> https://tank.fqdeng.com 纯 vibe 的，一行没写，就是有点烧 token ，godot 这块语料训练的挺多的，claude 能解决问题，有些问题也解决不了，我让盾牌竖着放，修改了一遍又一遍，在地图里面还是横着摆放的

（1203129 帖）> 整个项目 AI 贡献了 95%以上的代码，我只负责测试和细节调整。用的编辑器是 Antigravity ，主要模型是 Gemini 3.1 Pro 和 Claude Opus 4.6 ……等审核的这段又修修补补调整一些细节，基本都是在调样式，但总感觉怎么调都调不好。

**AI 搞不定的典型点**
> 我也是用 AI 在开发小游戏，现在用的 cocos2d ，但是一个很普通的弹窗背景不透明，和点击穿透，都没解决……用 claude 和 codex 都没解决
> 很多音频、特效、同步之类的复杂逻辑本身效果就难以量化，很多都是开发者不断微调出来的，现在的 AI 根本就处理不了这些复杂逻辑。
> 生成风格一致的游戏图片素材挺头疼
