# 掘金：《Claude Code给我做了个游戏，跑起来我沉默了》——一句话 Godot 横版跳跃的失败记录 + GameCraft-Bench

- 来源 URL：https://juejin.cn/post/7653097416624652314 （作者 Flynt，2026-06-21，经 r.jina.ai 获取全文）
- 模型/工具：Claude Code（模型未注明）+ Godot 4
- 游戏类型：2D 横版跳跃（猫收集金币、躲障碍）
- 结果证据：作者文字描述的失败现象（无链接/仓库）
- 热度：低（阅读 220）
- 生成方式：一句话起步，随后 2–3 轮"重新描述需求 / 问为什么跑不起来"

## Prompt 原文

> 帮我用Godot做个横版跳跃游戏，角色是一只猫，要收集金币，碰到障碍物就死。

## 失败现象（原文）

> 我点开运行——黑屏。好吧，可能是配置问题。我重新描述了一下需求，这次更详细了。还是黑屏。
> 第三次，我直接问了："为什么游戏跑不起来？" 它给我回了一段代码，让我手动替换。我照做了。
> 这次倒是进去了，但那只猫怎么在一坨透明的方块上跳？我完全分不清地面在哪里。金币更离谱，有的在屏幕外面，有的直接嵌在障碍物里面。
> 有次我让它加个暂停菜单……直接报错：`Invalid type 'Button' in method 'connect'`。我猜它是把Godot 3的语法用在了Godot 4的项目里。但这种事，它自己也不知道，用户得自己排查。

## 作者引用的基准（GameCraft-Bench，arXiv:2606.17861，港中大深圳/腾讯混元等）

> 140道题，15个游戏类别……用的是Godot引擎，给AI两个小时，又是写代码又是运行又是截图修改。评分标准是：内容丰富度35%、美术呈现35%、核心机制15%、画面功能性15%。
> 最强选手Claude Code配Opus-4.7，拿了41.46%。
> 核心机制得分55，内容丰富度39，美术呈现36
> AI需要提交操作录像，JSON格式的时间轴，记录鼠标键盘输入。系统自动重放验证你做的游戏能不能玩。
> 最低分是Codex配DeepSeek-V4-Pro的2.15%。

## 作者结论（原文）

> **AI很擅长做"能跑起来的代码逻辑"，但不擅长做"看起来像那么回事的游戏"**。
> 你让AI做一个"看起来很可爱的小猫收集金币的游戏"……但什么是"可爱"？……这些问题没有标准答案，AI很难猜对你的心意。

## 备注

典型失败组合：①引擎非 Web（Godot），agent 没有"运行→截图→自查"闭环，只能由人转述黑屏；②规格只有题材一句话，无参照原作、无验收标准；③Godot 3/4 API 混用这类版本幻觉，在没有运行反馈时 agent 自己发现不了。与成功案例（鱼皮以撒、riba2534）的差异主要在"agent 能否自己跑起来看结果"。
