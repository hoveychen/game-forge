# 怎么写 GDD

标杆是 `exemplars/open-blue.md`。下面是从它身上拆出来的东西：它有哪些部分、每部分为什么有效、换到别的品类要怎么变。Open Blue 学的是文档的密度和口吻；游戏本身为什么好玩，要从 `TEARDOWN.md`（第 2 步对品类标杆的拆解）里来，GDD 的数字和结构都要能对上它。

## 一、结构（按顺序，名字可以改，缺哪块要有理由）

| # | 部分 | 写什么 | Open Blue 里的样子 |
|---|---|---|---|
| 0 | 开头两句 | 暂名 + MVP 哲学（地理上小、系统上密；先证明「X 本身就有趣」）。技术与开发约定由 SKILL.md 第 7 步统一加在最前面，正文不写 | 「small geographically but systemically dense」 |
| 1 | 核心前提 | 一个**可玩的开场场景**：玩家是谁、为什么在这里、一句定调的台词 | 办公室、邮件不停弹、「I'm done」、带着 $205,000 离开 |
| 2 | 第一个有分量的选择 | 2–4 个**等价**选项，各列优势/劣势，配 ASCII 布局；明说「没有一个客观更好」，并讲清这个选择真正在选什么 | 三块同价地产：选的不是贵贱，是「想过什么样的生活」 |
| 3 | 世界 | 区域拓扑的 ASCII 图 + 尺寸数字 | 512×512，山—镇—矿—河—湖 |
| 4 | 视觉方向 | 参照混搭公式 + 「不是什么」+ **逐条列出要的视觉特性** + 角色尺寸/比例的数字 | 「Minecraft × OSRS × Stardew × Tiny Glade」；细致光照、软阴影、风吹植被、水面反射、烟囱冒烟；角色 6–8 体素宽 18–24 高 |
| 5 | 镜头与操控 | 精确参数、每个按键 | Pitch 35° / Yaw 45°，中键旋转，Shift+滚轮调高度，Q/E 转 45° |
| 6 | 系统，一个一节 | 成长阶梯（每级写具体名字）、一个带数字的校准锚点、「不应该只是……」、小流程图、等级提高影响什么 | 松树：3 级 7 下、5 级 5 下；「钓鱼不应该只是点水→等→出鱼」 |
| 7 | 系统之间的链 | 一张产出→消耗的链图，每种产出都有去处 | 伐木→制箭→狩猎→烹饪 |
| 8 | 第一段游玩 | 玩家头 10–20 分钟的流程图 + 「没有什么强迫他这样走」的自由点 | 「第一个早晨」+「Screw farming. I'm becoming a lumberjack.」 |
| 9 | 经济 / 数值表 | 带数字的表，并讲清它制造了什么心理 | $205,000 − $200,000 = $5,000，「地多钱少」；种子 $4、鱼竿 $35 |
| 10 | 节奏曲线 | 从 TEARDOWN.md 来：秒/分钟/小时三个尺度各是什么、多久一次；前 1–3 小时每个新东西出现的时刻表；一张**目标数值表**（用「我希望……」的口吻写数字，每条后面写怎么量），并指向 TEARDOWN.md 和 sim/。经营类必写；动作类写成每关逐段时长 | Open Blue 没有这一节（沙盒的节奏由技能阶梯隐含），范例见 exemplars/kairo-teardown.md：「有意义的新东西每 3–5 分钟、年度结算每 15–30 分钟」 |
| 10b | 关卡（玩家在手工设计的空间里推进的品类必写：线性关卡、箱庭、地牢、银河城、开放世界、沙盒里的地点） | 按 `levels.md` 写：结构类型和单元是什么 → 知识链表（每条知识在哪安全地看一次、在哪考、在哪换情境再考、终局怎么用）→ 空间结构图（单元怎么连、门槛在哪）→ 挑战单元卡（进门已会 / 一眼看到 / 先试的错法 / 洞察 / 线索 / 教会→考；单元多的写模板卡 + 样例卡 + 分布表）→ 节奏规则和冲突时怎么取舍。不要只写一行「这里有什么」 | Open Blue 没有关卡，箱庭地牢的范例见 exemplars/juanbian-cards.md |
| 11 | 界面 | HUD、弹窗、面板各画一个 ASCII 示意 | 左上时钟金钱、底部热键栏、升级弹窗、技能面板 |
| 12 | 锁住的未来 | MVP 之外的东西在 UI 上可见但锁住，让小游戏像一个大游戏的开端 | 🔒 Lv 6 ??? |
| 13 | MVP 边界 | 按类别列**具体清单和数字**（世界、角色、系统、敌人/动物、物品、配方、建筑、经济），最后写出 MVP 要回答的**一个问题**，以及答案是「是」之后怎么长 | 「Is living in this little voxel world fun?」 |
| 14 | 资产管线 | **每类资产从哪来、离线怎么变成游戏里的样子**：按资产类型分管线，每条写清源文件（自己画的像素图 / 参数文件 / 现成素材）、导入工具里的变换、烘焙产物，给一个源文件例子。运行时只加载产物 | 世界物体 → 语义重建成真体素体积；手持物品 → 深度估计后按像素剪影挤出 1–4 体素厚 |

长度参照：12k–25k 字符（用 Python `len` 数；macOS 上 `wc -m` 在某些 locale 下按字节数，中文会虚高到两倍多）。Open Blue 是英文约 17k；中文每个字信息量更高，同样的字符数内容会多一些，动作类要写手感和逐段关卡，会偏长；有关卡一节的，挑战单元卡另算（13 个单元约 5–8k 字符），上限为它放宽，卡不能删短。短于 10k 基本说明系统和内容没写到可执行的密度。

## 二、写法

1. **设计师的口吻。** 「我会……」「这一点很重要，因为……」。是在推销一个自己想做的游戏，不是在下达规格。模型会顺着这种热情去补全没写到的地方。
2. **每个决定都带理由。** 同价是为了让选择关于生活方式；只做 1–5 级是为了先证明生活本身有趣。没写到的地方，模型能顺着理由做出一致的决定。这比写死一百个数字有用。
3. **校准锚点，不穷举。** 每个系统给一两个带数字的例子，模型会推出风格一致的其余数值。
4. **大量「不要什么」。** 每个系统至少一条反默认约束，把模型从最平均的做法里拉出来一次。
5. **视觉野心要写成清单。** 这一段是给模型的打磨许可证。写「要有好看的光影」没用，写「软阴影、黄金时刻的斜射光、风吹草动、水面反射、烟囱的烟在夜里变暗」才有用。老板原话里带画质要求（「3A」「现代画质」）时，这一段要写得比 Open Blue 更长。
6. **多用 ASCII 图和小代码块。** 布局、流程、UI、数值表都画出来。它们比段落更不容易被误读，也让文档看起来像一个已经存在的游戏。
7. **数量用具体数字。** 「恰好 3 块地」「25–40 个配方」，不写「几个」「一些」。
8. **不写实现架构。** 除了资产管线（因为那是美术能否成立的关键），不写类结构、文件布局、测试方案。怎么做放权给模型。
9. **第一个选择的各选项共用同一套骨架。** Open Blue 的三块地只改变布局和资源分布，技能和经济完全共用。每个选项只在少数几处分叉，不要做成三套系统——那会让内容量翻倍，锚点摊薄，最后两个选项做成第一个的换皮。
10. **规模和锚点要匹配。** 写了多少东西，就要给多少锚点。建筑、单位、物品超过十来个时，用一张表把每一项的关键数字写全，而不是「其余照比例推」。
11. **游戏内文字用什么语言要写明。** 老板用中文，游戏 UI 默认中文。
12. **锚点从拆解里来。** 价格跨度、成长档位、解锁间隔这类数字，先拿 TEARDOWN.md 里标杆的数字当锚，再按本作调整，并写出为什么偏离。偏离标杆灵魂机制的地方，正文里要写出用什么顶上了它原来的功能（「组合不再只给加成，而是改变行为；为了让玩家照样经常撞出新组合，触发只看摆得够不够近，放下那一刻就揭晓」）。

## 三、品类：字数花在哪

Open Blue 是系统沙盒，字数花在系统阶梯和资源链上。别的品类要把同样的密度挪到它的乐趣所在的尺度上：

- **系统沙盒 / 经营 / 城建 / 生存**（乐趣在几分钟到几小时的积累）：资源链图、每个建筑/技能的阶梯和锚点、经济数值、第一段游玩的逐步流程，以及节奏曲线：什么时候出现下一个新东西，钱和想要的东西之间是不是一直差一点。发现类机制（组合、配方、相性）的乐趣来自频率，要有一批廉价、宽松触发、当场揭晓的条目撑着，贵的演出型条目放在上面点缀。对手 AI 要写清它**什么时候、做什么**（「第 20 分钟前后第一次来劫镖，带 6 人」），否则它永远不会行动。物流类游戏要写清玩家怎么**一眼看出哪里堵了**。
- **动作 / 射击 / 横版 / 地牢冒险**（乐趣在几秒的手感）：手感数字是承重墙——移速、跳跃高度和滞空时间、射速、子弹速度、命中停顿帧数、屏幕震动、敌人受击和死亡的反应动画、无敌帧，再加一张宽容机制表（门口角点修正、洞边宽容、输入缓冲、目标吸附，每条一个数字和理由）。手感数字是执行会话最会照做的东西，写全了就会被做出来，写法见 `levels.md` 第六部分。每个敌人一节（行为、攻击前摇怎么看出来、玩家用什么应对、怎么死得好笑/好看）。有关卡的按 `levels.md` 写知识链和挑战单元卡，不要只写逐段的秒数和「出什么」。Boss 分阶段写，每个阶段的打法都要能在知识链里查到前面哪里教过。用名作校准：「跳跃手感像合金弹头 X：起跳快、下落略快于上升、空中可转向」。
- **内容驱动（解谜、叙事、梗）**：内容本身就是设计，要把样本真正写出来——第一场戏的台词、前 5 个谜题（按 `levels.md` 的挑战单元卡写，每道题的洞察不重复）、10 个梗事件的完整文本。「加上各种梗」这种要求，就在 GDD 里列出具体的梗和它在游戏里怎么触发。
- **混合品类**：分清主次，主品类按上面写满，次品类写到能闭环为止。

## 四、美术路线：选一条做得到好看的

执行会话开工前会先用生图工具按这一节做概念设计图，之后照着图造资产和打磨；但最终画面靠几何、shader、导入工具、现成素材和生图工具出的贴图做出来，所以概念图画得出来不等于游戏做得出来。GDD 必须选一条**能生产到高水准**的美术路线，并在资产管线一节写清楚怎么造。所有造型手段都发生在离线导入阶段，产物烘焙成网格和贴图：

- **体素**：像素图或参数文件 → 导入工具体素化 + 贪婪网格 + 烘焙 AO，配好光照。Open Blue 已证明可以惊艳。
- **程序化低多边形 / 风格化 3D**：由基本体拼装、倒角、顶点色或程序化纹理，配合现代光照（PBR、SDFGI/VoxelGI、体积雾、SSR、SSAO、辉光、景深、GPU 粒子、贴花）。「3A 现代画质」的要求走这条路，重点写**光照、材质、后处理、特效、破坏**，而不是写模型精度。
- **现成素材 + 统一化**：CC0 / 可商用的模型、骨架和动作库、PBR 材质先拿来，在导入管线里统一比例、材质和调色板。角色动画尤其该走这条，自己 key 帧的动作很难看。
- **SDF / 程序化建模**：适合有机形体，作为导入工具里的造型手段，结果烘焙成网格。运行时的光线步进只用于云、液体、雾、特效。
- **程序化动画**：叠在骨骼动画上的反向动力学、挤压拉伸、次级运动，能让很粗的模型显得生动。

不管选哪条路线，**形体和表面分开造**：形体（轮廓、比例、体块）由上面的手段造，表面细节交给生图工具。概念图里让人觉得精致的东西，大多是表面信息——屏幕内容、海报、招牌和铭牌上的字、书脊、布料花纹、木纹、划痕、地面的苔藓和石板——这些靠顶点色和手写几何永远做不到，靠生图工具出图几乎不花几何成本。写资产管线时按这几招安排：

- **平面卡片**：屏幕、海报、白板、招牌、相框、书架正面这类本来就是平面的东西，生图出图、打成图集，模型上只给这一块平面 UV。场景「塞满东西」的密度主要来自这一层。
- **可平铺材质**：布料、木头、金属、石头、地表等，生图出可平铺的 albedo，再推出法线 / 粗糙度，按材质或区域 ID 在 shader 里采样。模型没有 UV 时用三平面投影（triplanar），带动画的模型用动画前的静止坐标做投影，纹理才不会在动作时漂移。
- **贴花**：污渍、手印、涂鸦、裂纹、表情，生图出带透明通道的贴花图集，运行时用贴花或 UV 偏移切换。
- **复杂物件**（椅子、机器、植物这类基本体拼不像的）：先找 CC0 / 可商用模型进管线统一化；找不到就用简化形体加卡片取巧——植物用几片带透明通道的叶丛卡片交叉摆放，机器用一个圆角盒加生图出的面板贴图。
- **其余位图资产**：UI 图标、物品图标、角色头像、角色五官和表情贴图、面板和按钮底图、天空盒和远景、粒子贴图（烟、火花、光斑、碎屑）、加载图和过场插画，也都由生图工具出，导入工具负责切图、抠透明、缩放、打图集。不要写成代码拼 SVG、绘图库按坐标画形状或 shader 现算；需要实时变化的部分（昼夜、云的流动、进度条）才用 shader 或代码，叠在生图的底子上。

所有生图都拿 concept/ 里的概念图当风格参考（用 fleet__image_edit 带参考图出），不要每张单独抽卡，否则风格散掉。贴图打成图集、移动端用压缩格式，同类实例共用材质。

人脸要分开看：五官和表情是表面信息，按上面的办法由生图出贴图，以设定图的表情表为参考投到脸部 UV 上，表情靠换贴图；难的是脸的形体，写实或近景特写的脸靠脚本雕不出来。镜头不需要近看脸时，就用头盔、护目镜、兜帽、小尺寸、非人角色绕开。选定路线后，视觉方向一节的每个特性都要是这条路线做得到的。

## 五、自检清单（写完逐条过）

1. 通读全文：有没有任何一句是流程、审批、验收、里程碑、测试、「暂定」语言？有就删。
2. 老板原话的每个关键词，分别落在哪一段？逐个指出来。找不到的就补。
3. 核心前提是不是一个能玩的场景，而不是一段背景设定？
4. 第一个有分量的选择：选项是否等价、各有代价？（品类天然没有的可以不写，但要想过。）
5. 每个系统：有阶梯（具体名字）、有数字锚点、有「不应该只是」？
6. 每种产出都有去处吗？
7. 有第一段游玩流程，而且有一个自由偏离点？
8. 视觉特性清单 ≥ 8 条具体项，且都是选定美术路线做得到的？
9. 有 HUD / 弹窗 / 面板的 ASCII 示意？
10. 有节奏曲线一节：三个时间尺度、前几小时的时刻表、目标数值表（数字写出来、每条写怎么量、用「我希望」的口吻）？有经济的品类，sim/ 里的纸面模拟跑过了吗？现金 ÷ 下一件想要的东西大部分时间 < 1、等待时间合理、没有哪条解锁链在前三分之一就走完？
10b. 有关卡的品类：写明了结构类型和单元是什么吗？知识链表里每条「第一次考」前面都有「安全地看一次」吗？Boss 和终局的每个打法都能倒查到出处吗？顺序不由设计者定的（银河城、开放世界），按 `levels.md` 第三部分多查的那一步做了吗？空间结构图按类型查过了吗（地牢有环、银河城每个能力锁先被看到、开放世界写了密度和视线）？每个单元都有卡，或者有模板卡 + 样例卡 + 分布表？逐张问自己：「先试的错法」真的会失败吗？只经历过前面那些单元的玩家，能从线索推到洞察吗？节奏规则之间的冲突写了怎么取舍吗？
11. 每一处偏离 TEARDOWN.md 里灵魂机制的地方，正文都写了用什么顶上它的功能吗？用贵的内容替代廉价内容的地方，频率谁来撑？
12. MVP 清单每类都有具体数字，最后有「要回答的一个问题」？
13. 有资产管线一节，每类资产写清源文件、离线变换、烘焙产物？有没有哪类资产被写成运行时现场生成？表面细节（平面卡片、平铺材质、贴花）写了从生图工具出、怎么上到模型上吗？还是全靠顶点色和几何？图标、头像、角色五官和表情、天空、粒子贴图这些位图资产写了从生图工具出，而不是代码画？管线里的重计算（SDF 求值、体素化、AO）写了用什么算吗——GPU compute 或原生库，而不是脚本逐点循环？
14. 长度 12k–25k 字符？
15. 和 `exemplars/open-blue.md` 并排读：密度、具体程度、野心相当吗？如果你是编码 agent，读完会不会想立刻开干，而且知道该做一个多大的东西？
